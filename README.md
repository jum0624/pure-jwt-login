# pure-jwt-login
- 스프링 시큐리티를 사용하지 않고, 인터셉터로 인증 로직 구현하기
- 실제 프로젝트에 도입하기 전, 간단한 벤치마크를 구현해보며 검증하기 위한 프로젝트입니다.

# 도입과정
## 📌 세션+JWT 하이브리드 인증 시스템 구축
### 배경 
모놀리식 기반 서비스의 MSA 전환 진행 중, 신규 모바일 쿠폰 발급 기능 추가 요건이 발생. 해당 기능은 향후 독립 서비스로 분리될 것을 고려해 가맹점 식별값을 담은 JWT 기반 인증이 필요했으나, 기존 관리자 페이지는 세션 기반 인터셉터 인증 체계로 운영 중이었음.

### 과제
두 인증 체계를 공존시키면서 기존 코드 변경을 최소화하고, 신규 기능에는 MSA에 적합한 JWT 인증을 선제 도입해야 했음.

## 💡 기술적 의사 결정 과정
- 기존 코드 전면 토큰 인증방식 교체 vs 하이브리드 방식 병행
  - 운영 서비스 특성상 전면 교체는 리스크가 크다고 판단 → 세션 인증을 유지하면서 JWT 인증을 병행 지원하는 하이브리드 구조 채택
- SpringSecurity 사용 vs Interceptor 직접 구현
  - 기존 프로젝트에 SpringSecurity가 없는 구조였고, 도입 시 전체 인증 흐름 재설계 필요
  - 기존 Interceptor 구조를 활용해 JWT 검증 로직을 직접 추가하는 방식 선택

## 💡 구현 내용
- Interceptor 레이어에서 쿠키의 JWT 토큰 검증 로직 구현 (SpringSecurity 미사용) → 간단한 벤치마크 구현 후 실제 프로젝트에 적용하는 방식으로 검증
- 쿠키 토큰 무효 시 세션 강제 초기화 후 로그인 리다이렉트 처리 (세션-토큰 불일치 방지)

## 💡 문제 해결 경험
### 인터셉터 기반 토큰 인증 및 ThreadLocal 활용
인터셉터에서 토큰을 검증하는 인증 방식을 구현하는 과정에서, 서비스 로직마다 쿠키에서 토큰을 직접 꺼내기 위해 HttpServletRequest를 파라미터로 계속 전달해야 하는 문제가 발생했습니다. 이로 인해 비즈니스 로직을 담당하는 서비스 레이어가 웹 계층 객체에 의존하게 되는 구조적 문제가 있었습니다.
인터셉터의 preHandle에서 쿠키의 토큰을 파싱해 유저 정보를 추출한 뒤 ThreadLocal에 저장하고, 요청이 끝나는 postHandler에서 제거하는 방식을 적용했습니다. 이를 통해 Spring Security의 SecurityContextHolder와 동일한 역할을 하도록 했습니다. 또한, 서비스 레이어가 HttpServletRequest에 의존하지 않고도 어디서든 유저 정보를 꺼낼 수 있게 되어, 웹 계층과 비즈니스 계층의 관심사를 분리할 수 있었습니다.

### 세션과 토큰 하이브리드 인증 환경의 불일치 문제 해결
세션과 JWT 두 인증 수단이 독립적으로 동작하여, 쿠키가 만료되어도 세션이 살아있어 로그아웃이 되지 않는 문제가 발생했습니다.
Interceptor의 preHandle에서 쿠키 유효성을 검사하고, 토큰이 무효한 경우 session.invalidate()로 세션을 강제 종료한 뒤 response.sendRedirect()를 사용하여 이전 요청 정보 없이 로그인 페이지로 리다이렉트했습니다. 이를 통해 토큰 만료 시 세션도 함께 종료되어 두 인증 수단이 일관되게 동작하게 되었습니다.
